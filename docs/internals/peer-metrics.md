# Peer metrics

The [event catalog](../../apps/server/src/peerHub/core/metricsCatalog.ts) is the boundary: the queued writer projects every record before writing or notifying listeners. Ordinary coordination logs carry counts, sizes, timings, short protocol identifiers and opaque task references. Unknown events retain only their name and time; unknown fields are dropped. This boundary holds with the metrics plugin off.

Debug detail stays local and opt-in. Settings limits it to 24 hours; `PEER_COORDINATION_DEBUG=1` forces it for labs. Re-enabling replaces the file; restoring the deadline after restart keeps it. Never upload debug detail. A streaming scrub replaces legacy logs and their rotated copy once, drops invalid lines and leaves no original. A v2 header prevents repeated rewrites.

Add events to the catalog before recording them. Counts use `*Count`, tallies `*Counts`, and failures `*Class`; original text belongs only in debug detail. Untracked task ids can be titles, so task ids and `task:` scopes use the `task` kind. Clients join `taskRef` to the work view. Protocol identifiers must never contain emails, paths or knowledge-entry slugs.

The broker bridge separates metric fields from detail and stamps workspace, project and adapter. Adapter identity comes from the durable Mod handshake. `intent.failed` is diagnostic: only `intent.unverified` with `wentOn` counts an edit that proceeded without a verdict. Counting both would overstate failures; a late Hub answer may still count that edit twice.

The [collector](../../apps/server/src/peerHub/plugins/metrics/rollup.ts) subscribes only in its plugin's scope. It never replays the raw log, supplies agent text or runs in the work-pass lock. The work pass exposes its immutable shell and policy snapshot plus a lazy, narrow provider-turn reader; observers use only that pass, bound reads per pass and seed existing history instead of backfilling it. Normalized provider input already includes cached input; cached columns are a subset, never added to input again. Unavailable/subagent usage remains explicitly partial.

UTC day files and consent state have private permissions and atomic replacement. Today stays mutable; completed days cache until pruning or erasure. Flush errors keep dirty state and retry independently of hooks. Task references, PR observations, cursors and extension metric names are bounded. Histograms use the shared 21 edges; percentiles are upper bounds, including the final over-14-days bucket. Missing measurement differs from a measured zero, including the Hub's explicit zero-valued basis markers.

Sharing belongs to the signed-in email on this environment, independently of the workspace admin switch. Uploads are cumulative snapshots with nondecreasing revisions, consent-start dates, bounded backfill and one request per workspace. Changing the Hub epoch discards old markers and prevents historical resurrection. An owed erase blocks uploads, survives restart, and retries only for its original email; an upload timeout requires a second erase after 60 seconds. Sign-out and plugin turn-off wait at most five seconds for each erase, in parallel across workspaces, and retain local day files. Membership cleanup also applies while inactive.

The Hub folds its ledger because devices cannot observe outcomes across computers. Sweeps follow thread/session reports and run inside them; the fold cursor and bounded overlap/task basis persist together. Configuration changes use the `cfg:` fence so an interrupted sweep cannot write through a disabled switch or a new epoch. Team device sums require three distinct source computers; Hub outcomes remain independently available. Scope and source stay explicit in RPC responses, cards and exports, which travel through the environment connection in local, remote and tunnel clients.
